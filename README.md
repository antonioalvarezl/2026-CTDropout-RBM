Code for the numerical experiments in

> A. Álvarez-López and M. Hernández, *Convergence, design and training of
> continuous-time dropout as a random batch method*,
> [arXiv:2510.13134](https://arxiv.org/abs/2510.13134), 2025.

## What is this?

**Neural ODEs** model depth as continuous integration of a learned vector field.
**Dropout** — randomly silencing neurons during forward passes — is a standard
regulariser in discrete networks, but applying it in continuous time raises new
challenges: naïve masking can break the ODE solver's convergence guarantees.

This work frames **continuous-time dropout as a random batch method (RBM)**. At
each time interval of length *h*, a random subset of neurons is sampled and the
output is rescaled to keep the estimator unbiased (Horvitz–Thompson correction).

python -m venv .venv && source .venv/bin/activate

## Experiments

| Script | Paper result |
| --- | --- |
| `exp1_trajectory_convergence` | Trajectory error and sampling design |
| `exp2_objective_consistency` | Strong and weak objective consistency, and a sampling-scheme comparison |
| `exp3_measure_transport` | Coupling, pointwise density, and `L1` errors |
| `exp4_work_accuracy` | Work against accuracy, and against test loss |

Add `--quick` for a small smoke run; without it the scripts use the paper
settings.

```bash
python -m experiments.exp1_trajectory_convergence
python -m experiments.exp3_measure_transport
python -m experiments.exp4_work_accuracy
```

`exp2` evaluates a frozen control and never trains, so it needs a trained
classification model. `exp1` writes one, so run that first and then:

```bash
python -m experiments.exp2_objective_consistency
```

It adopts the most recent `exp1` run, prints the checkpoint and dataset it took,
and verifies that the saved dataset is exactly what the checkpoint's seeds
regenerate before integrating anything. Pass `--checkpoint` for a different
model, or `--base-run-dir` to look elsewhere.

## Results and figures

Each run writes a new `results/expN/run-<UTC timestamp>/` holding

```text
data/         result tables (CSV) and raw samples (NPZ)
figures/      PDF
config/       settings and software versions
checkpoints/  trained model
manifest.json seeds, Git commit, device, precision, timestamp
```

New computations receive distinct directories. `--plots-only` replaces the
figures in the selected run; result tables and checkpoints are retained.
Figures use saved tables, so they can be restyled without new simulations:

```bash
python -m experiments.exp1_trajectory_convergence --plots-only
```

That reuses the most recent run. Pass `--output-dir <run>` to plot a specific
one. To supplement an existing run without retraining or a full sweep:

```bash
python -m experiments.exp1_trajectory_convergence --diagnostics-only --output-dir <exp1-run>
python -m experiments.exp3_measure_transport --diagnostics-only --output-dir <exp3-run>
```

These write a new `diagnostics-<timestamp>/` inside the source run. Exp1 checks
the observation mesh on ten original schedules at two fine-range endpoints,
Lambda quadrature/Monte Carlo uncertainty, and the first three partitions plus
the contiguous baseline. It also saves revised figures, leaving originals intact.
Exp3 checks spatial and temporal density refinement on up to three original
schedules per h. Neither option replaces a final scientific run.

Plotting style lives in `experiments/_style.py`; each experiment's figures
are built in its own `*_plots.py`.

## Paper section and illustration panels

[`numerical_experiments.tex`](numerical_experiments.tex) is the LaTeX section for
the manuscript. It expects the figure PDFs in a `Figures/numerics/` directory of
the paper project; copy them there from the run folders above. Panels carry no
embedded titles or legends — the captions identify colors and markers — so the
`\includegraphics` groups can be rearranged without rerendering.

The illustration panels come from the frozen `exp1` classifier and `exp3` flow
and train nothing:

```bash
python -m experiments.exp3_measure_transport --qualitative
```

That takes the most recent `exp1` and `exp3` runs (override with
`--classification-dir` / `--output-dir`). Each panel is written beside the run
that produced the model it shows, so the classification panels land in the
`exp1` run's `figures/`:

```text
classification_initial.pdf                     the pooled input cloud
classification_trajectory_{full,random}.pdf    real RK4 paths at h = 2^-11
```

and the transport panels in the `exp3` run's:

```text
transport_densities.pdf                        initial and terminal density level sets
transport_{full,random}_samples.pdf            the 1024-sample clouds
transport_density_{full,random}_evolution.pdf  rho_0 plus four KDE times
transport_density_initial_final.pdf            initial and terminal on one axes
```

The transported-density figures draw the analytic initial density of the paper
and, at four equispaced later times, a Gaussian KDE of 20000 simulated
trajectories, all as level sets on one shared scale, so the visible lightening
is the physical spreading of mass rather than a per-panel rescaling. The
adjacent `qualitative_config.json`, `classification_trajectory_config.json` and
`transport_density_evolution_config.json` record sources, fixed schedules, KDE
bandwidths and numerical checks.

## Notes on the numerics

- Runs are double precision on CPU. The root seed is `2026`; per-purpose seeds
  are derived from it and recorded in the manifest.
- Trajectory intervals use a grouped jackknife over schedules. Slope intervals
  approximately propagate those SEs, assuming independent samples across h;
  they do not quantify departures from a power law. Lambda and new partition
  evaluations record schedule/draw uncertainty. Historical partitions without
  saved group contributions have no recoverable per-partition MC interval;
  the diagnostic subset does not supply intervals for the other partitions.
- Each experiment measures its own discretisation error, in `reference_check.csv`
  and `dt_refinement.csv`. Density diagnostics compare individual paired
  schedules at each h, avoiding cancellation between signed errors. Refinement
  differences are diagnostics, not certified error bounds; extrapolating a
  difference from one h to the entire sweep is not justified.
- The theorems give upper bounds. Fitted slopes in `slope_fits.csv` are
  descriptive, and each records the range it used. A slope different from one
  does not contradict an O(h) upper bound.
